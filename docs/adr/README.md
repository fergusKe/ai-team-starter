# ADR — Architecture Decision Records

**只記難逆轉、有取捨的決策。** 用什麼 log 套件不用寫 ADR；
用不用 monorepo、資料放哪、認證怎麼做，要寫。

判準：**六個月後有人問「為什麼當初選這個」，你答得出來嗎？**
答不出來就該寫。

檔名 `NNNN-短標題.md`，編號遞增，不重複使用。

決策被推翻時**不要刪舊的** —— 新開一份，在舊的標 `Superseded by NNNN`。
被推翻的決策跟現行決策一樣有價值：它記錄了你們試過什麼。

## 架構邊界要多標兩欄

ADR 裡**講的是系統之間的邊界**（誰可以 import 誰、訊息只能走哪條路、高頻資料放哪）
的那些，在開頭的欄位多加兩行：

```
- **邊界狀態**: 已強制 | 僅約定 | 已知缺口
- **證據**: tests/foo.test.ts:42、src/bar.ts:10
```

| 狀態 | 意思 | 證據要連到什麼 |
|---|---|---|
| `已強制` | 違反了**會有測試或檢查變紅** | 至少一條是 `tests/` 底下或 `.github/scripts/` 的檔案 |
| `僅約定` | 只有規格／ADR 說「應該」，程式碼沒有擋 | spec、ADR、或現況的 src |
| `已知缺口` | 規格說有這條邊界，**而且知道現在守不住** | 守不住的那個位置 |

**`已強制` 不接受 spec 或 ADR 當唯一證據** —— 它們說的是「應該」，說不了「真的」。
一份 ADR 說「已強制」而證據是另一份文件，等於用一句話證明另一句話。

沒標的 ADR（`未標`）不是錯 —— 量測紀錄、技術選型不是邊界，不用標。

`bash .github/scripts/arch-view.sh` 會把這些欄位讀出來列成一張表，證據路徑不存在、
狀態拼錯、已強制卻沒連到測試，它會報。**它驗不了測試是不是 `test.skip`** ——
路徑存在只代表有交卷。要確定真的鎖住，做一次突變（見 `docs/adr/0007` 的做法）。

**這些欄位是 ADR 唯一會「過期」的部分**：缺口補上了要改成已強制、證據的行號漂了要改。
其他段落是歷史，不改。
